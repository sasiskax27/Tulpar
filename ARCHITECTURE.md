# Tulpar — архитектура редактора

> Рабочее название: **Tulpar** (тулпар — крылатый конь из казахских легенд: быстрый и лёгкий). Название можно поменять в любой момент.

Редактор с ощущением VS Code, но лёгкий, без телеметрии, открытый для любых AI-агентов, совместимый с расширениями VS Code и настраиваемый глубже любого другого редактора.

---

## 1. Принципы («супер баланс»)

Каждое решение в проекте проверяется по этим правилам. Если фича их нарушает — она не попадает в ядро.

1. **Быстрый старт.** Холодный запуск меньше 1 секунды, в простое — меньше 150 МБ памяти.
2. **Ноль телеметрии.** Редактор сам ничего не отправляет в сеть. В сеть ходит только то, что вы запустили явно: языковые серверы, агенты, git, установка расширений.
3. **Умный по требованию.** Языковой сервер стартует, только когда открыт файл его языка. Агент — только когда открыта панель агента. Хост расширений — только если установлено расширение с кодом. Закрыли — процесс остановлен.
4. **Маленькое ядро.** В ядре: редактор, файлы, поиск, терминал, git, палитра команд. Остальное — подключаемое.
5. **Агенты — полноправная часть.** Любой ACP-агент подключается строчкой в настройках.
6. **Настраивается всё.** Нет ни одной части интерфейса или поведения, которую нельзя изменить без пересборки редактора.

Сквозное правило: **ощущается как VS Code** — те же сочетания клавиш, та же раскладка панелей, тот же движок набора текста, те же форматы настроек и расширений.

## 2. Стек

| Слой | Технология | Почему |
|---|---|---|
| Оболочка приложения | **Tauri 2** | Системный веб-движок вместо встроенного Chromium → приложение в разы легче Electron |
| Ядро (бэкенд) | **Rust** | Скорость, надёжность, всё тяжёлое (файлы, поиск, процессы) вне интерфейса |
| Интерфейс | **TypeScript + SolidJS** | Реактивность без виртуального DOM, очень маленький размер |
| Редактор | **Monaco** | Тот самый движок из VS Code |
| Подсветка | **vscode-textmate + vscode-oniguruma**, позже **tree-sitter** | Грамматики VS Code для любого языка; tree-sitter — для структуры кода |
| Терминал | **xterm.js** + крейт `portable-pty` | Тот же терминал, что в VS Code |
| Поиск по проекту | Крейты `ignore` + `grep` (библиотеки ripgrep) | Скорость ripgrep, учёт `.gitignore` |
| Слежение за файлами | Крейт `notify` | Мгновенное обновление дерева файлов |
| Git | Крейт `gix` (gitoxide) | Чистый Rust, без внешних зависимостей |
| Языки | **LSP** | Один клиент → любой язык |
| Отладка | **DAP** | Один клиент → отладка любого языка |
| Агенты | **ACP**, крейт `agent-client-protocol` | Один клиент → любой агент |
| Расширения VS Code | Реестр **Open VSX** + свой хост расширений на Node.js | Законный доступ к экосистеме VS Code |
| Пользовательские скрипты | TypeScript в изолированном Web Worker | Кастомизация кодом без Node.js и без риска для редактора |
| Сборка интерфейса | Vite | Быстрая сборка и горячая перезагрузка |

## 4. Как части общаются

```
┌──────────────────────────── Интерфейс (WebView) ────────────────────────────┐
│ Monaco · Вкладки · Дерево · Поиск · Терминал · Git · Отладка · Агенты       │
│ Скрипты пользователя (Web Worker, только через публичный API)               │
└───────────────┬─────────────────────────────────────────────▲───────────────┘
        invoke (запросы)                               events (потоки)
┌───────────────▼─────────────────────────────────────────────┴───────────────┐
│                              Ядро на Rust                                   │
│ workspace · search · terminal · git · settings · extensions                 │
│ lsp ──stdio──► pyright, rust-analyzer, gopls, clangd …                      │
│ dap ──stdio──► debugpy, codelldb, delve …                                   │
│ acp ──stdio──► Claude Code, Gemini CLI, Codex, свой агент                   │
│ extension-host ──rpc──► расширения VS Code с кодом (только если установлены)│
└─────────────────────────────────────────────────────────────────────────────┘
```

- **Запрос–ответ** (открыть файл, найти текст, получить diff) → `invoke`.
- **Потоки** (терминал, ответ агента, диагностика, изменения на диске) → события.
- Интерфейс, скрипты и расширения никогда не трогают диск и процессы сами — только через ядро.

## 5. Поддержка всех языков: пять слоёв

Ни один язык не поддерживается «вручную». Каждый слой пишется один раз и работает для сотен языков.

### 5.1 Подсветка
- **Грамматики TextMate** (формат VS Code) через `vscode-textmate`. Любое расширение VS Code с грамматикой сразу даёт подсветку нового языка.
- **Tree-sitter** (второй месяц): понимание структуры кода — умное выделение блоков, сворачивание функций, точные отступы, индекс символов.

### 5.2 Ум кода — LSP с автоустановкой
Файл `~/.config/tulpar/languages.json`:

```jsonc
{
  "python":     { "server": "basedpyright-langserver", "args": ["--stdio"], "install": "pip:basedpyright" },
  "typescript": { "server": "typescript-language-server", "args": ["--stdio"], "install": "npm:typescript-language-server" },
  "rust":       { "server": "rust-analyzer", "install": "github:rust-lang/rust-analyzer" },
  "go":         { "server": "gopls", "install": "go:golang.org/x/tools/gopls@latest" },
  "cpp":        { "server": "clangd", "install": "github:clangd/clangd" }
}
```

Открыли файл `.go`, сервера нет → «Установить gopls?» → один клик. Серверы ставятся в `~/.local/share/tulpar/servers/`, не засоряя систему.

### 5.3 Отладка — DAP
Один клиент: точки останова, пошаговое выполнение, переменные, стек вызовов для Python, C/C++, Rust, Go, JS и других. Конфигурации в формате `launch.json` из VS Code.

### 5.4 Запасной режим (если у языка нет сервера)
- Автодополнение по словам из открытых файлов
- Переход к определению по индексу символов (ctags, позже tree-sitter)
- Автоопределение отступов и поддержка `.editorconfig`
- Комментирование строк, парные скобки и кавычки (из `language-configuration.json`)

### 5.5 Мелочи
- Определение языка по расширению, имени файла (`Dockerfile`, `Makefile`) и шебангу
- Сниппеты в формате VS Code
- Форматтеры и линтеры через универсальный мост (efm-langserver): prettier, black, rustfmt и другие

## 6. Расширения VS Code

### 6.1 Откуда брать
Только **Open VSX** (open-vsx.org) — открытый реестр Eclipse Foundation. Условия Microsoft Marketplace разрешают его использование только в продуктах Microsoft, поэтому подключать его в Tulpar нельзя. Также можно установить `.vsix` из файла.

Некоторые расширения Microsoft (Pylance, C/C++, Remote) по своей лицензии работают только в VS Code. У них есть открытые замены: basedpyright, clangd и т.д. — они идут в списке рекомендуемых.

### 6.2 Три уровня совместимости

| Уровень | Что это | Примеры | Как делаем | Когда |
|---|---|---|---|---|
| **1. Декларативные** | Расширение — это только JSON и файлы, без кода | Темы, иконки, грамматики языков, сниппеты, раскладки клавиш, конфигурации языков | Читаем `contributes` из `package.json` и применяем сами. Без Node.js | Месяц 1 |
| **2. Обёртки над серверами** | Расширение лишь запускает языковой сервер | Многие языковые расширения | Берём сервер напрямую через автоустановку LSP | Месяц 1 |
| **3. Расширения с кодом** | Расширение выполняет JavaScript через API `vscode` | GitLens, линтеры, интеграции, свои инструменты | Свой хост расширений на Node.js, реализующий API `vscode` | Месяц 2–3 |

Уровни 1 и 2 покрывают большую часть того, что люди реально ставят: темы, языки, сниппеты.

### 6.3 Хост расширений (уровень 3)
- Отдельный процесс Node.js, запускается **только** если установлено хотя бы одно расширение с кодом. Иначе ни памяти, ни процессов.
- Реализует модуль `vscode` по частям, начиная с самого используемого: `commands`, `window` (сообщения, статус-бар, quick pick), `workspace` (файлы, настройки), `languages` (провайдеры автодополнения, hover, диагностика), декорации редактора.
- Webview-панели расширений, отладочные адаптеры из расширений, удалённая разработка — позже.
- Каждое расширение видит в Tulpar статус совместимости: «полностью», «частично (нет X)», «не поддерживается».
- Чтобы не изобретать всё заново, изучаем открытые реализации того же API: Eclipse Theia и OpenVSCode Server.

Честно: полная совместимость со всем API VS Code — это работа на месяцы. Цель — чтобы 20–30 самых популярных расширений с кодом работали, а остальные — по мере необходимости.

## 7. Кастомизация: «настраивается всё»

Пять уровней — от простого к мощному. Всё перезагружается на лету, без перезапуска.

### 7.1 Настройки — `settings.json`
Те же ключи, что в VS Code (`editor.fontSize`, `editor.tabSize`, `workbench.colorTheme`…), чтобы можно было перенести свои настройки копированием.

### 7.2 Клавиши — `keybindings.json`
- Формат VS Code: перенос своих сочетаний один в один.
- **Режимы**: обычный, vim, emacs — или свой, с собственными режимами и последовательностями клавиш.
- Любое действие в Tulpar — команда, значит любое действие можно повесить на клавишу.

### 7.3 Раскладка — `layout.json`
То, чего не хватает в VS Code: панели — не жёсткие слоты, а дерево, которое описывается в конфиге.

```jsonc
{
  "layouts": {
    "Код":    { "left": ["explorer"], "center": ["editor"], "bottom": ["terminal"], "right": ["agent"] },
    "Фокус":  { "center": ["editor"] },
    "Ревью":  { "left": ["git"], "center": ["diff"], "right": ["agent"] }
  },
  "default": "Код"
}
```

Переключение раскладок одной командой. Любую панель можно поставить куда угодно, включая несколько терминалов или два дерева файлов.

### 7.4 Внешний вид — `user.css`
- Вся тема Tulpar — это CSS-переменные и стабильные имена классов, они документированы как **публичный API**.
- Можно поменять что угодно: шрифт вкладок, высоту строки статуса, вид дерева, анимации.
- Темы VS Code (JSON) загружаются и переводятся в те же переменные.

### 7.5 Скрипты — `init.ts`
Самый мощный уровень: свой код, который расширяет редактор. Выполняется в изолированном Web Worker — не может сломать или замедлить редактор и работает только через публичный API.

```ts
import { tulpar } from "tulpar";

// Своя команда
tulpar.commands.register("my.todayNote", async () => {
  const date = new Date().toISOString().slice(0, 10);
  await tulpar.workspace.openFile(`notes/${date}.md`, { create: true });
});

// Макрос: цепочка команд на одну клавишу
tulpar.keys.bind("ctrl+alt+s", ["editor.format", "file.save", "git.stageCurrent"]);

// Хук: при сохранении Python-файла — запустить тесты в терминале
tulpar.on("save", (file) => {
  if (file.language === "python") tulpar.terminal.run("pytest -q");
});

// Свой элемент в строке статуса
tulpar.statusBar.add({ text: "☕ перерыв", command: "my.break" });

// Свой агент на кнопку
tulpar.agents.ask("Мой агент", "Объясни выделенный код", { context: "selection" });
```

### 7.6 Профили
- **Глобальные** (`~/.config/tulpar/`) и **проектные** (`.tulpar/` в корне проекта) — проектные дополняют глобальные.
- Именованные профили («Python», «Веб», «Презентация») со своими настройками, расширениями, раскладкой и темой.
- Весь конфиг — обычные текстовые файлы, их можно хранить в git и переносить между компьютерами.

## 8. Агенты через ACP

ACP — открытый протокол «редактор ↔ агент», как LSP, но для AI. Редактор запускает агента как подпроцесс и общается с ним по JSON-RPC.

```jsonc
// settings.json
{
  "agents": {
    "Claude Code": { "command": "claude-code-acp" },
    "Gemini CLI":  { "command": "gemini", "args": ["--experimental-acp"] },
    "Мой агент":   { "command": "/home/me/agents/my-agent", "args": ["acp"] }
  }
}
```

| Агент просит | Что делает Tulpar |
|---|---|
| Прочитать файл | Отдаёт текущий текст, включая несохранённые правки |
| Записать файл | Показывает diff → вы принимаете или отклоняете |
| Выполнить команду | Спрашивает разрешение, запускает в видимом терминале |
| Разрешение на действие | Диалог: «один раз / всегда для этого проекта / нет» |

Агенты доступны и из скриптов (`tulpar.agents`), так что можно строить свои сценарии: агент на сохранение, агент для ревью коммита и т.д.

## 9. Производительность

| Метрика | Цель |
|---|---|
| Холодный старт | < 1 с |
| Память в простое (1 проект, 5 вкладок, без расширений с кодом) | < 150 МБ |
| Открытие файла 10 МБ | < 300 мс |
| Поиск по проекту на 100 тыс. файлов | < 2 с |

- Языки, грамматики и тяжёлые панели загружаются лениво.
- Файлы > 5 МБ открываются в облегчённом режиме.
- Неактивные языковые серверы и хост расширений останавливаются после простоя.
- Каждое расширение и скрипт видны в «Мониторе процессов» Tulpar: сколько памяти и времени запуска они стоят.

## 12. Риски

| Риск | Что делаем |
|---|---|
| Разные веб-движки на разных ОС | Тестируем каждую неделю на всех целевых ОС |
| API VS Code огромный | Делаем по частям, начиная с самого используемого; изучаем Theia и OpenVSCode |
| Нужного расширения нет в Open VSX | Установка из `.vsix`, рекомендация открытых замен |
| Хост расширений делает редактор тяжёлым | Запуск только по требованию, монитор процессов, отдельный процесс |
| Скрипты пользователя ломают редактор | Изоляция в Web Worker, доступ только через публичный API, таймауты |
| Кастомизация превращается в хаос | Всё — текстовые конфиги с JSON-схемами, автодополнением и проверкой ошибок |
| Слишком много всего | План по месяцам, раздел 11 держим жёстко |

## 13. Что нужно, чтобы начать

1. **ОС**, на которой работаете (и нужны ли остальные).

4. Установленные **Rust** (rustup) и **Node.js 20+** на вашем компьютере для сборки.
5. **Список расширений VS Code**, которыми вы пользуетесь сейчас — по нему определим приоритеты хоста расширений.
